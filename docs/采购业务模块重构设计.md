# 采购业务模块重构设计

> 目标：拆分「采购订单」与「收货单」为独立单据，支持**一单多收**、**部分入库**；新增「采购退货单」。

> 【2026-10 更新】收货单已退役，业务流简化为「采购订单 → 入库 → 出库」：
> - 采购订单页「收货入库」弹窗确认本次实收数量后，后端直接生成采购入库单（`wms_purchase_in`，
>   新增 `source_order_id` / `source_order_no` 来源列）并完成入库（入库确认即审核，复用入库单状态机与移动加权成本）。
> - 入库管理页（`/warehouse/inbound`）统一展示 `wms_purchase_in`，支持「来源采购订单」列；
>   手动入库仍为草稿，由「完成」动作审核后入库。
> - 收货单路由（`/purchase/receipts`）、接口（`/api/v1/purchase-receipts`）与按钮权限（菜单 632、按钮 651/652/653）已删除；
>   `wms_purchase_receipt` 表与历史数据只读保留，采购退货仍可关联历史收货单。
> - 数据库变更脚本：`backend/src/main/resources/db/upgrade-purchase-receive.sql`。
>
> 本文档中涉及收货单的表结构、状态机、接口与路由描述均为退役前的设计记录，仅作历史参考。

## 1. 业务模型

```
采购订单 pms_purchase_order          ← 业务意图：我要订什么
   │ 1:N
   ▼
采购订单明细 pms_purchase_order_item  ← ordered_qty / received_qty / returned_qty
   │ 收货（可多次、可部分）
   ▼
收货单 wms_purchase_receipt           ← 物理事实：实际到了什么
   │ 1:N
   ▼
收货单明细 wms_purchase_receipt_item   ← 实收数量

采购退货单 pms_purchase_return        ← 红字：退给供应商
   │ 1:N
   ▼
采购退货单明细 pms_purchase_return_item
```

### 1.1 核心数量字段

采购订单明细：

| 字段 | 含义 | 约束 |
|---|---|---|
| `ordered_qty` | 订购数量 | 采购时填写 |
| `received_qty` | 已收数量 | 每次收货累加，≤ ordered_qty |
| `returned_qty` | 已退数量 | 每次退货累加，≤ received_qty |

不变量：`received_qty + 本次收货量 <= ordered_qty`、`returned_qty + 本次退货量 <= received_qty`

### 1.2 状态机

**采购订单** `pms_purchase_order.status`

| 值 | 名称 | 可编辑 | 说明 |
|---|---|---|---|
| 0 | 草稿 | ✅ | 明细可自由增删改 |
| 1 | 待审核 | ❌ | 已提交，等待审核 |
| 2 | 已审核 | ❌ | 审核通过，可开始收货 |
| 3 | 部分收货 | ❌ | 有收货但未收完 |
| 4 | 已完成 | ❌ | 全部收齐（或收齐后关闭） |
| 5 | 已取消 | ❌ | 终止 |
| 6 | 部分退货 | ❌ | 有退货但未退完 |
| 7 | 已退货 | ❌ | 全部退回 |

状态由明细汇总**自动推导**，不手工维护：
- 已审核后，每收到货 → 3（部分收货）或 4（全部收齐）
- 发生退货 → 6（部分退货）或 7（全部退回）

**收货单** `wms_purchase_receipt.status`

| 值 | 名称 | 说明 |
|---|---|---|
| 0 | 草稿 | 可编辑明细 |
| 1 | 待审核 | 待审核 |
| 2 | 已审核 | 审核通过，待入库 |
| 3 | 已入库 | 已生效，库存已增加 |
| 4 | 已作废 | 作废，回滚库存 |

**采购退货单** `pms_purchase_return.status`

| 值 | 名称 | 说明 |
|---|---|---|
| 0 | 草稿 | 可编辑明细 |
| 1 | 待审核 | 待审核 |
| 2 | 已审核 | 审核通过，待退货 |
| 3 | 已退货 | 已生效，库存已减少 |
| 4 | 已作废 | 作废，恢复库存 |

> 说明：收货单与退货单都是「审核」与「生效」两个独立动作，因此需要「已审核待生效」这一中间态。
> 审核通过只改变单据状态（可反审核），实际库存变动发生在「入库」/「确认退货」。

### 3. API 契约

统一前缀 `/api/v1`。所有响应走 `Result<T>`，分页走 `PageResult<T>`。

#### 3.1 采购订单 `/api/v1/purchase-orders`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/purchase-orders` | 分页查询（keyword/orderNo/supplierId/storeId/status/时间范围） |
| GET | `/api/v1/purchase-orders/{id}` | 详情（含明细与各数量汇总） |
| POST | `/api/v1/purchase-orders` | 新建（草稿） |
| PUT | `/api/v1/purchase-orders/{id}` | 编辑（仅草稿） |
| DELETE | `/api/v1/purchase-orders/{id}` | 删除（仅草稿） |
| PUT | `/api/v1/purchase-orders/{id}/submit` | 提交审核（草稿→待审核） |
| PUT | `/api/v1/purchase-orders/{id}/review` | 审核通过（待审核→已审核） |
| PUT | `/api/v1/purchase-orders/{id}/revoke-review` | 撤销审核（待审核→草稿） |

### 4. 库存影响

| 动作 | 库存 | 采购明细 | 采购单状态 |
|---|---|---|---|
| 收货单入库 | `warehouse_quantity += qty` | `received_qty += qty` | 3 或 4 |
| 收货单作废 | `warehouse_quantity -= qty` | `received_qty -= qty` | 重算 |
| 退货单确认 | `warehouse_quantity -= qty` | `returned_qty += qty` | 6 或 7 |
| 退货单作废 | `warehouse_quantity += qty` | `returned_qty -= qty` | 重算 |

所有库存变动写 `wms_stock_log`（log_type：1-采购入库，6-入库回退），与既有约定一致。

### 6. 数据迁移

- 旧表 `wms_purchase_in` / `wms_purchase_in_item` 保留但不再使用（不删表，避免破坏历史引用）
- 迁移脚本清空旧采购数据：`DELETE FROM wms_purchase_in_item; DELETE FROM wms_purchase_in;`
- 新表初始为空

### 7. 兼容策略

- 前端 `api/warehouse.ts` 中映射 `purchase-in` 的逻辑**保留但停用**（仓库管理的「入库单」页改指向新收货单接口）
- 旧接口 `/api/v1/stock/purchase-in/**` 后端保留不动（不再被前端调用），待新链路稳定后再清理
